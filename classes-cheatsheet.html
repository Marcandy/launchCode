JavaScript Classes — Pocket Reference

Quick review of everything we covered. Glance, recall, repeat.

1 · Anatomy of a Class

A class is a blueprint with two halves:

  • constructor — runs once per new. Sets up per-instance data.
  • methods — shared behavior. Live on the prototype, not the instance.
class Vehicle {
  constructor(make, mileage = 0) {
    this.make = make;       // data → instance
    this.mileage = mileage;
  }
  drive(distance) {           // behavior → prototype
    this.mileage += distance;
  }
}
→ Constructor sets DATA. Methods define BEHAVIOR.

2 · Where Data & Methods Live

Three vehicles, one shared drive(). Different data — same function in memory.

Instancemakemileage
car'Honda'38000
truck'Ford'1200
moto'Honda'80

All three point to the same Vehicle.prototype, which holds drive() and getDetails() — one copy total, ever.

→ DATA differs per object (instance). BEHAVIOR is shared (prototype).

3 · The this Keyword

Inside a method, this = whichever object you called the method on.

car.drive(500);     // inside drive: this === car
truck.drive(1200);  // inside drive: this === truck

drive(distance) {
  this.mileage += distance;   // updates whoever called
}
→ One shared function, but this makes it operate on the right object.
→ Methods take NO "self" argument — this is automatic.

4 · Inheritance — extends + super()

Book is-a LibraryItem with extras. The child REUSES the parent.

class LibraryItem {
  constructor(title, id, isAvailable = true) {
    this.title = title;
    this.id = id;
    this.isAvailable = isAvailable;
  }
}

class Book extends LibraryItem {
  constructor(title, id, author) {
    super(title, id);     // ← pour the foundation
    this.author = author;  // ← then put up the walls
  }
}
WRONG ORDER
this.author = author;
super(title, id);
✗ ReferenceError
RIGHT ORDER
super(title, id);
this.author = author;
✓ works

5 · super() — What You Pass Matters

super(...) is just a function call to the parent's constructor.

CallWhat the parent gets
super(title, id, false)All values passed explicitly
super(title, id)isAvailable uses its default (true)
super()All params → undefined / defaults kick in
(no super at all)✗ ReferenceError — this blocked
→ Empty super() is LEGAL — parent runs with undefined inputs.
→ MISSING super is ILLEGAL — child can't touch this yet.
→ Foundation first. Always.

6 · Where Does State Live?

Put state at the LOWEST level where it's still shared by everything beneath.

QuestionPut it where
All children need it, same default?Parent (with default param)
All children need it, different defaults?Parent — pass via super(...)
Only some children need it?Child class
Varies per individual instance?Instance property / closure
→ isAvailable belongs on the parent (all share, same default). loanPeriodDays (varies by type) belongs on the child.

7 · Composition — Don't Always Extend

"Prefer composition over inheritance." When extends feels heavy, skip it.

// Factory function — no class, no super
function makeBook(title, id, author) {
  return {
    title, id, author, isAvailable: true,
    checkout()   { this.isAvailable = false; },
    returnItem() { this.isAvailable = true;  }
  };
}
→ Inheritance = "is-a" (Book IS-A LibraryItem)
→ Composition = "has-a" / loose mixing. Easier to refactor, less ceremony.
→ Use inheritance when types really share an interface; otherwise compose.

8 · Closures (Bonus)

A function that "remembers" variables from where it was created — like carrying a backpack of context wherever it goes.

function makeCounter() {
  let count = 0;
  return function() {
    count += 1;
    return count;
  };
}

const c1 = makeCounter();
const c2 = makeCounter();
c1(); c1(); c1();   // 1, 2, 3
c2();              // 1 — totally separate!
→ Each call to the factory builds a NEW function with its OWN private state.
→ Used for per-instance behavior, private data, and "remembering" setup values.

9 · Quick Gotchas & Mental Models

  • this = the object on the left of the dot.
    car.drive() → this === car. No caller? this === undefined (strict mode).
  • Methods belong to the CLASS. Properties belong to the INSTANCE.
    Writing this.drive = function(){} in the constructor copies it per instance — usually wrong.
  • super(...) is just a function call to the parent constructor.
    Must run before any this.x = ... in a derived constructor. Foundation → walls.
  • Closures = a function carrying a "backpack" of variables from where it was made.
    Used for per-instance behavior or private state. Each call to the factory = new backpack.
  • Class fields (ES2022): isAvailable = true; outside the constructor works too.
    Cleaner default declarations. Doesn't change inheritance rules — super() still required.
